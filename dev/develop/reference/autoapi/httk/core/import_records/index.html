httk.core.import_records¶

Stdlib-only import records: what happened while importing one thing into a store.

An ImportRecord is the canonical record of one import: where the thing came from, which importer imported it, the outcome, and every warning, notice and exception reported on the way, as ImportReport children in emission order. A source holding several things gives one import record per thing, each with the reports that apply to it.

ImportRecord itself records failures and exclusions only, which embed no entry, e.g. a failure before the kind of the imported thing is known. A successful import is recorded by a typed subclass that adds one record-valued field holding the imported entry and extends __post_init__ to require it exactly when status == "imported"; it gives its own StorageInfo and registers in the imports family.

The record carries the internal, unprefixed entry-type name imports; the provider prefix is applied at the serving edge.

classmethod from_log_record(record)[source]¶

Build a report from a log record, e.g. one collected by collect_reports().

The message is reduced to what identifies the diagnostic on any machine:

  • A captured Python warning (logger py.warnings) becomes "<Category>: <text>" from the first line of its formatted text, without the path:line: prefix and the source line; continuation lines of a multi-line warning message are dropped.

  • A blank message becomes "(empty message)", so a silent record does not abort the import.

  • An attached exception adds one line "<ExceptionType>: <text>"; the traceback is left out, since it holds absolute paths.

The context extra becomes one context, several joined with ", ", or None when there is none.

Parameters:

record (logging.LogRecord) – The log record.

The report.

class httk.core.import_records.ImportRecord[source]¶

The record of importing one thing into a store.

This base class records failures and exclusions only; a successful import is recorded by a typed subclass that embeds the imported entry.

Two imports are one record when source, importer, outcome and reports are equal; a new importer version gives a new record. imported_at and the entry metadata are outside content identity and equality. Equality also compares the embedded source_file, whose url and name are outside its identity, so two records with equal content ids compare unequal when the file was recorded under another location.

Parameters:

  • source_uri – Where the thing was imported from, as chosen by the importer: a stable path, URL or identifier, not a machine-specific absolute path.

  • importer – The program that imported the thing, with its version.

  • status – The outcome: "imported", "failed" or "excluded".

  • source_item – The item within the source when it holds several, e.g. a CIF data block name.

  • source_file – The source bytes, if recorded.

  • reports – The diagnostics, in emission order; any iterable, stored as a tuple.

  • error – The exception or exclusion text; required unless status is "imported", and None when it is.

  • repaired – Whether the importer had to repair the source; only with status == "imported".

  • imported_at – When the import was made, a timezone-aware datetime; kept from the first save.

  • id – The human-readable entry id shared by all revisions; minted by the store when None.

  • immutable_id – The per-revision immutable id; minted by the store when None.

  • last_modified – The optional timezone-aware metadata timestamp.

Raises:

  • TypeError – If a field has the wrong type.

  • ValueError – If a required string is blank, source_uri, importer or source_item has surrounding whitespace, status is unknown, error or repaired disagrees with status, a timestamp is naive, or a base ImportRecord has status == "imported".
