httk.core.curation¶

Stdlib-only curation records: notes, tags, and external database entries.

Any stored entry can be weakly linked to a Note (a dated remark), a Tag (a key with an optional value), and an ExternalDatabaseEntry (one entry of an external database), besides a ReferenceRecord. STANDARD_LINKS declares these four links and standard_links() tells which classes get them: every entry record, that is a dataclass with both an id and an immutable_id field, except the four link targets themselves.

The records carry the internal, unprefixed entry-type names notes, tags and external_database_entries; the provider prefix is applied at the serving edge. Like every record they are content-deduplicated, and weak links bind lineages, so they stay local to one store.

class httk.core.curation.Note[source]¶

A dated remark by some entity, linked from the entries it is about.

Notes are content-deduplicated: the same date, source, and text is one entry, possibly linked from many entries. Code that wants to change a note for one linking entry only must therefore unlink the shared note and link a new one, rather than replace the shared note.

Parameters:

  • date – When the note was made, a timezone-aware datetime chosen by its source; not the time it was stored.

  • source – The entity that made the note: a person, a group, or a program with its version.

  • text – The note itself, as free text.

  • id – The human-readable entry id shared by all revisions; minted by the store when None.

  • immutable_id – The per-revision immutable id; minted by the store when None.

  • last_modified – The optional timezone-aware metadata timestamp.

Raises:

  • TypeError – If a field has the wrong type.

  • ValueError – If source or text is blank, or a timestamp is naive.

class httk.core.curation.ExternalDatabaseEntry[source]¶

One entry of an external database, linked from the entries related to it.

database_provider names the provider of the external database: its OPTIMADE provider prefix (as registered in the OPTIMADE providers list), e.g. "cod", "oqmd", "mp", or an equivalent short lowercase name when no registered prefix exists. database identifies the specific database of that provider; None means the provider’s only or main database.

role says how the linking entry relates to the external entry and is part of the content identity: None for a general relation, "origin" when the linking entry was obtained from the external entry. An entry may have several origins, unordered. url is outside the content identity, so the same external entry with and without a known URL is one entry. On a deduplicating save the first non-null url is kept and a later, different url is ignored (KeepStored); once a non-null url is stored it is kept: neither save nor replace changes it.

The reference describing the whole external database is linked through this record’s own references weak link.

Parameters:

  • database_provider – The provider of the external database, by the convention above.

  • database – The short identifier of the provider’s database; None for its only or main one.

  • entry_id – The identifier of the entry in that database, as that database writes it.

  • url – A URL of the entry in that database, if available.

  • role – How the linking entry relates to the external entry: None or "origin".

  • id – The human-readable entry id shared by all revisions; minted by the store when None.

  • immutable_id – The per-revision immutable id; minted by the store when None.

  • last_modified – The optional timezone-aware metadata timestamp.

Raises:

  • TypeError – If a field has the wrong type.

  • ValueError – If database_provider, database, entry_id or role is blank or has surrounding whitespace, database_provider or database contains whitespace, or last_modified is naive.
